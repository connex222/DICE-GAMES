# Pocket Gamebox — TV multiplayer (first playable phase)

The original seven solo/local browser games are untouched. This branch adds a real server-authoritative **Shut the Box** TV + phone experience for 2–8 people as a multiplayer foundation. The other six games **are not yet wired to the server**.

## Run locally
`npm install`
`npm start`
Visit http://localhost:3000/multiplayer.html on the host screen. Guests on the same network can use the host computer's LAN address, or use a publicly HTTPS-hosted instance to join from different networks.

## Host and join
1. Host chooses **Host a TV game** and sees QR + room code.
2. Guests scan QR on their phones or enter the room code via **Join on phone**. Their browser retains a secret reconnect token.
3. Host starts once 2–8 players join. The TV shows the public board and standings; only the active player can roll and pick tiles on their phone.
4. **End turn** automatically occurs when no valid tile combination is available; otherwise the active player can select tiles matching the roll.
5. Lowest score wins. Play again retains the player order.

### Security and operations
- All dice come from the server's cryptographically secure random source.
- Players cannot submit roll results or other players' actions. The host cannot make players' moves.
- Room/player codes and reconnect tokens are generated with crypto; private tokens never appear in room broadcasts.
- Room limit 8, basic rate-limits and payload-size limits; idle rooms expire.
- WebSockets require a single persistent Node web service; **static GitHub Pages cannot host them**.
- In-memory rooms currently reset on deployment/server restart. Single-instance deployment only; scaling requires persistent shared room state.
- QR generated by same server, and always uses the active server origin. Verify the printed URL is the public HTTPS Render URL before testing real phones.
- Audio, advanced modes and other six-game multiplayer integrations remain outstanding.

## Deploy
The included `render.yaml` is a proposed blueprint for a Render web service. Setting up a paid service needs explicit approval; do not claim deployed until an actual public Render URL is tested.

## Acceptance tests before release
- 2 and 8 independent handsets on Wi-Fi and cellular
- QR scan, manual code, full game, results, rematch
- Unauthorized action and out-of-turn rejection
- Refresh/reconnect, host refresh, disconnect mid-turn, expired room
- TV 1080p/4K; phone 320/390/430 px; tablet landscape
- Browser audio permissions, voiceover and keyboard accessibility
